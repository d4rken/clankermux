# Devin subscriptions and SWE-2

ClankerMux supports Devin CLI session accounts through its Messages and Responses interfaces. The provider discovers the account's available models and resolves the `swe-2` alias to an enabled SWE-2 variant. Claude family requests map to that alias by default. The central Routing page can select a concrete discovered model, and account model permissions control which models may be sent. Devin aliases resolve to an enabled concrete model before the request’s routing decision is frozen. Adaptive model routing is not supported.

## Connect an account

In **Accounts → Add account → Devin**, enter a name and choose **Sign in with Devin**. Open the authorization link, sign in with your Devin account, and paste the full localhost callback URL into the form. A browser error on the localhost page is expected when the dashboard server is remote. Complete sign-in within ten minutes.

Alternatively, import a **Devin CLI session token** and use **Check access and models**. A cloud API key (`cog_…`) is a different credential. Account creation verifies the session before saving it. Passwords are never requested; tokens and PKCE verifiers are not returned by the account API. Expired or revoked session tokens require a new sign-in. The account menu’s **Reconnect** action accepts either browser sign-in or a replacement CLI session token and updates that account in place. Known user IDs must match; account history, settings, and manual pauses are preserved. A successful reconnect clears only a pause caused by rejected credentials.

Account cards show the authenticated email, account ID, plan, and organization name when Devin supplies them. Organization IDs appear separately in the identity tooltip and reconnect details. Devin does not report an account rate-limit tier, so that field stays unset. Identity is saved on creation and successful metadata polls, with cached metadata providing the latest values. The refresh button fetches account and usage metadata without inference and invalidates the credential-scoped metadata cache first.

For a local development checkout, `bun scripts/devin-login.ts` opens a loopback callback listener and prints a browser link. It stores the result in ignored `.cache/devin-login/credentials.json` with mode `0600`. If the browser cannot reach the callback, save its full URL to a private local file and run `bun scripts/devin-login.ts --complete /path/to/callback-url.txt`. When your browser runs on another computer, forward the printed callback port over SSH (`ssh -N -L <port>:127.0.0.1:<port> <user>@<server>`) before opening the link. Keep that tunnel open until sign-in finishes. Do not paste session tokens or callback codes into chat, logs, or issues.

After local sign-in, `bun scripts/devin-check.ts` reads plan and model metadata without inference. `bun scripts/devin-check.ts --smoke` makes two bounded SWE-2 requests to verify a tool-call roundtrip; it consumes a small amount of included quota and keeps quota protection enabled. To check another entitled model, add its discovered ID, for example `--smoke --model swe-1-6-slow` for the verified Free-account model.

## Credential lifecycle

Devin’s CLI login contract does not expose a refresh-token grant. ClankerMux renews short-lived request JWTs using the session token and never invents a session-renewal endpoint. Known JWT expiry shortens the metadata cache lifetime; a metadata authentication rejection is retried once, while permission errors and temporary service failures do not trigger that retry. Confirmed rejected session credentials pause normal routing with a reconnect-needed status. Normal requests can refresh authentication and retry the same account once before output starts; forced requests retain their no-replay behavior.

Session expiry is displayed only when the token carries a usable expiry claim. Opaque tokens have unknown expiry, and metadata polling replaces older nominal expiry placeholders with the actual claim or an unknown value. Tokens and decoded claims are never logged. Authentication failures preserve an existing manual or quota pause rather than overwriting its reason; reconnect remains available from the account menu.

## Quota behavior

Daily and weekly allowances retain their actual calendar reset times. Neither is represented as a five-hour session. Quotas are shared with Devin CLI, Desktop, and cloud use. The account dashboard displays the windows actually reported by Devin, including plans without a daily window.

Included quota protection starts enabled. Before inference, the provider reads cached account status (at most 30 seconds old, invalidated at a reported reset) and refuses known exhausted quota or an unknown included allowance. Reported included prompt/flow credits can authorize credit-based free accounts. Prepaid balance alone does not count as included quota. The account policy menu’s **Allow requests beyond verified included quota** switch disables this gate, including the refusal when a free account does not report its allowance. Enable it only after checking the account and intended spending policy.

This is an observed-quota gate, not a spending guarantee: simultaneous requests and use outside ClankerMux can consume the remaining allowance between observations. Keep prepaid overage disabled in Devin for a provider-enforced spending limit. Requests default to subscription billing classification; exact per-request Devin prepaid charges are not reconciled into the payments ledger.

## Account automation

**Auto-recover quota** is an opt-in account policy. With included quota protection enabled, fresh metadata can proactively pause that account when its included allowance is exhausted or unknown. The same policy resumes quota-paused accounts after metadata proves included capacity is available, provided a current cooldown has elapsed. Recovery preserves manual pauses and reconnect-needed states, and checks the current credential, endpoint, and policy values before applying a change. Defaults retain request-time quota checks without enabling proactive pausing.

This automation uses metadata only. Daily and weekly windows reset at their reported timestamps; inference is not needed to start them. No warm-up request is sent, and the generic five-hour auto-refresh scheduler is not enabled for Devin. Normal routing priority and existing session affinity continue to apply after recovery. A reported loss of CLI entitlement leaves quota automation inactive; it is a separate access problem. If a plan never reports included allowance, recovery waits for evidence. To use that account anyway, review **Allow requests beyond verified included quota** and then resume it manually.

## Supported transport

The dedicated provider uses Devin's native Connect/protobuf services, adapting text, tool calls/results, base64 images on capable models, reasoning/signatures, and usage into Messages JSON or SSE. The Responses interface uses the existing canonical Messages conversion. Token counts are local estimates. Opaque redacted thinking from another provider is omitted; other content that cannot be represented is rejected explicitly. Automatic tool selection is supported. Forced `tool` and `any` choices are rejected explicitly: the native descriptor exposes named forcing, but live attempts did not produce the requested tool call. `none` sends no tool definitions.

Connect errors can arrive with HTTP 200. A bounded initial stream peek converts early failures into HTTP errors before retry/failover; later failures become SSE error events without replaying delivered output. Parsed late errors are recorded as failed requests even when the HTTP response has already started with status 200. This correction applies to all providers using the shared SSE path, so their reported success rates can decrease when previously misclassified errors occur. Non-quota errors do not trigger quota cooldowns. Normal and forced routing both normalize responses. Raw HTTP observations preserve the original upstream status; final request history and retry decisions use the normalized result.

Binary upstream bodies contain credentials. Request recording retains the canonical client JSON rather than these protobuf bytes. Internal model metadata headers are removed before network forwarding. Metadata authentication uses a bounded, credential-scoped cache; provider-directed endpoint changes must remain on the original origin or approved Devin/Cognition vendor domains.

## Sources and validation limits

Protocol declarations and codec are MIT-licensed adaptations from [OhMyPi at commit 3b3a6dc](https://github.com/can1357/oh-my-pi/tree/3b3a6dc9bbd85102ce19d0b1c11bf6870915f6ec). Full attribution and update details are in `packages/providers/src/providers/devin/vendor/`. The adapter follows its Devin provider, discovery, usage, and PKCE implementations. Chat metadata uses official CLI release `3000.10.21`, whose Linux archive SHA-256 was checked against the release manifest on 2026-09-11 (`7cac6f5739ba3a3e5542f3b7fa07ed902d6dfb96ca22e4c63ae84c03bb7db47c`); discovery retains OhMyPi’s development-channel identity. The OpenCode and Pi repository trees examined did not identify an equivalent Devin provider; OhMyPi supplied the concrete protocol reference.

Official references: [SWE-2 launch](https://cognition.com/blog/swe-2), [billing](https://docs.devin.ai/admin/billing/self-serve), [CLI commands](https://docs.devin.ai/cli/reference/commands), and [CLI troubleshooting](https://docs.devin.ai/cli/troubleshooting).

Mocked protocol, proxy, account API, quota polling, and dashboard tests cover integration behavior. Live verification on 2026-09-11 confirmed sign-in, model discovery, and daily/weekly quota discovery on a Free account. Devin disabled SWE-2 High, Medium, and Max with “Upgrade to Pro to access this model.” The enabled SWE-1.6 Slow model completed a real tool-call/result roundtrip with automatic tool selection. Two named-forcing attempts returned thinking only; forced tool selection is not validated. SWE-2 inference still needs verification with an entitled account. The native CLI protocol is not a published stable third-party inference API; future upstream changes may require updating the adapter and its pinned descriptors.

## Harness verification

On 2026-09-11, OpenCode 1.18.30, OhMyPi 18.1.16, and Pi 0.85.1 on `cnc` were exercised through the worktree proxy's OpenAI Responses interface with the Free account's `swe-1-6-slow` model. Each used an isolated configuration, a separate proxy API key, and an identical disposable project. Each completed four model turns: two file reads, a source edit, a shell test, and a final acknowledgment. The supplied tests passed without changes to the test file. Final runs verified input, cached-input, and output token reporting at both the harness and proxy, with exact per-turn counts matching. Cache-hit rate is cache-read input divided by uncached input plus cache-read and cache-write input; cache writes are not hits and output tokens are excluded. The twelve turns reported 60,672 cache-read and 330 uncached input tokens (99.46% combined hit rate). This measures provider-side caching. Analytics include reported tokens from successful and failed requests unless filtered by outcome; missing usage contributes no tokens to the ratio, while the request still counts toward success/error rates. All six original harness configuration/auth files retained their hashes, permissions, and sizes. Temporary configurations, keys, database, test server, and SSH tunnel were removed after verification.

These runs exposed two shared Responses adapter defects, now covered by regression tests: easy messages with omitted `type` or string content were dropped, and input/cache counts arriving in final streaming usage updates were lost. System/developer messages now become the canonical system prompt without rewriting the original body retained for native Responses accounts. Usage translation includes cached input in the Responses total and preserves separate cache details. Devin also rejects an empty conversation before inference with a clear local error.

This verifies ClankerMux's translation path, not the harnesses' native Devin integrations. It does not establish SWE-2 entitlement or inference behavior on paid plans.
